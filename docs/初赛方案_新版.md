# 初赛方案_新版

## 1. 摘要

“黔址优选”v2 面向社区便利店与轻餐饮两类业态，构建“区县背景约束下的网格级多因子商业选址推荐模型”。项目以贵阳市典型区县为试点，将官方宏观经济指标和就业数据用于市场背景说明，将高德行政区划与 POI 数据用于空间样本统计，最终输出 1km 评价网格推荐、地图洞察、指标解释和 Markdown 选址报告。

## 2. 项目定位

本项目不是门店地址预测工具，而是面向企业前期调研和政府社区商业布局参考的智能选址原型。

核心边界：

- 业务对象：社区便利店、轻餐饮。
- 研究范围：云岩区、南明区、观山湖区，增强版扩展花溪区、白云区。
- 推荐对象：1km 评价网格。
- 数据定位：官方数据说背景，高德 POI 说空间样本，模型结果说评分与解释。

## 3. 数据基础

| 数据类型 | 来源 | 用途 |
|---|---|---|
| 官方宏观经济指标 | 赛事官方数据 | 贵州省级市场、消费与区域发展背景说明 |
| 官方就业数据 | 赛事官方数据 | 贵州省级就业背景与数据适用边界说明 |
| POI 数据 | 高德 POI API，百度和腾讯作为后续备选 | 网格级商业、交通、生活配套、竞品和共生业态统计 |
| 行政区划 | 高德行政区划 API | 区县基础信息、边界和中心点 |
| 地图展示 | 高德 JS API 2.0、Streamlit components；Folium 兼容回退 | GCJ-02 推荐网格地图、评分图层和结果提示 |
| 离线复现输入 | `data/processed/` 中已跟踪的区县、边界、网格和 POI 样本 | 无 `AMAP_KEY` 时复现指标、评分、地图和模板报告 |

当前仓库已经完成 v2 高德区县、网格与 POI 样本链路，并将旧版 OSM/GIS 实现隔离到 `src/legacy/v1/`。默认运行不重新联网，而是使用已跟踪的 Step 4–6 输入完成离线复现；在线刷新必须显式使用 `python scripts/run_pipeline.py --refresh-amap` 并配置 `AMAP_KEY`。

## 4. 技术路线

```text
官方宏观经济与就业数据
→ 贵阳市典型区县选择
→ 高德行政区划与 POI 数据接入
→ 1km 评价网格生成
→ 网格 POI 统计
→ 多因子评分
→ 便利店和轻餐饮差异化推荐
→ 地图展示
→ 智能报告生成
→ Streamlit 商业选址工作台展示
```

## 5. 指标与模型

v2 评分围绕以下可解释指标构建：

- 交通可达性。
- 消费潜力。
- 就业/办公客群代理。
- 共生业态。
- 竞争压力。
- 商业氛围。

竞争压力为负向指标，评分时转为竞争适配得分。官方宏观经济和就业数据不硬拆到 1km 评价网格，只用于背景说明和报告解释。

## 6. 前端展示

前端目标是“黔址优选商业智能选址工作台”，包含：

- 项目总览。
- 数据底座。
- 区域对比。
- 网格推荐。
- 地图洞察。
- 智能报告。
- 项目说明。

核心演示链路：

```text
选择业态
→ 选择目标区县或全部
→ 查看 Top 10 评价网格
→ 查看地图洞察
→ 选择一个 grid_id
→ 生成 Markdown 选址报告
```

## 7. 限制说明

- 当前不声称获取全量高德 POI。
- 当前不做门牌号级推荐。
- 当前不承诺具体盈利。
- 当前不生成真实租金、真实客流或真实营收预测。
- 当前不把省级或市级就业数据硬拆到 1km 评价网格。
- 当前仓库没有可直接使用的 `data/demo/` 文件；不得把缺失的离线文件描述为已具备能力。
