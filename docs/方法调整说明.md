# 方法调整说明

## 1. 调整结论

项目 v2 主线从旧版 OSM/GIS 空间处理与两阶段筛选，调整为：

> 区县背景约束下的网格级多因子商业选址推荐模型。

新的核心对象是贵阳市典型区县内的 1km 评价网格。区县用于限定研究范围、承载市场背景说明和结果分组展示，不再作为最终推荐对象。

## 2. 为什么不再以 Geofabrik/OSM 为主数据源

旧版已经基于 Geofabrik 贵州 OSM GPKG 完成图层盘点、空间特征提取和演示结果生成。该链路保留为 legacy 参考。

v2 不再以 Geofabrik/OSM 为主数据源，原因是社区便利店和轻餐饮选址更依赖门店、餐饮、学校、医院、商场、写字楼、小区、公交站等 POI 样本。中国境内商业 POI 的覆盖、分类和更新频率通常更适合从国内 LBS 平台获取。

v2 主线改为：

- 高德行政区划 API：获取目标区县基础信息和边界信息。
- 高德 POI API：获取网格周边 POI 样本。
- 官方宏观经济指标和就业数据：作为市场背景和消费能力说明。
- 离线演示数据：在未配置 `AMAP_KEY` 时保障演示。

## 3. 为什么只做贵阳市典型区县

当前项目是比赛原型，不适合在没有稳定 API 配额、缓存和人工核验机制前覆盖全省。贵阳市典型区县更适合演示完整方法链路：

- 区县数量可控。
- 城市商业 POI 密度更高。
- 便利店和轻餐饮场景更贴近社区商业需求。
- 演示时更容易解释市场背景、空间差异和推荐结果。

第一版范围为云岩区、南明区、观山湖区；增强版再扩展花溪区和白云区。

## 4. 为什么区县只作为背景约束

区县数量较少，直接用区县平均分做最终推荐会掩盖内部差异。v2 中区县承担三类作用：

- 限定 API 查询和网格生成范围。
- 展示官方数据背景与区县分组结果。
- 支撑前端筛选和对比。

最终排序仍以 1km 评价网格为准。

## 5. 为什么 1km 评价网格是核心评分对象

1km 评价网格能够在原型阶段兼顾空间粒度、数据可得性和解释性：

- 比区县更能体现社区商业空间差异。
- 比具体门店地址更稳健，也更符合当前数据边界。
- 可统一承载交通、消费潜力、就业/办公客群代理、共生业态、竞争压力和商业氛围等指标。
- 便于在地图和工作台页面中展示。

## 6. 高德 POI 数据的使用边界

高德 POI API 在本项目中用于原型验证和样本统计。文档和页面不得声称获取全量高德 POI，不得绕过 API 限制，不得把 demo 数据包装成真实 API 结果。

当前 60 个样本网格采用统一的关键词、500 米查询半径、分页上限和统计规则。该数据适合用于同一口径下的网格相对比较，但不能解释为各网格真实、完整的 POI 总量。

分类编码 6 网格核验显示，3 个关键词统计全零网格在分类编码查询下仍为零，说明这些零值没有表现出普遍的查询失效。6 个网格的分类编码计数总和高于关键词计数，但两种查询的召回口径不同，且分类编码中的餐饮大类与快餐、小吃、咖啡、茶饮等细分类存在交叉。类别计数总和的差异不能直接解释为唯一 POI 数量或评分质量同比例变化。

本项目采用以下工程决策：

- 优先保证 60 个网格的数据口径一致、过程可复现和结果可比较。
- Step 7 继续使用现有关键词统计，不混入 6 网格分类编码核验数据。
- 关键词数据用于相对密度、相对强弱和相对排序，不用于声明绝对设施总量。
- 分类编码核验作为敏感性检查，用于说明不同查询口径可能造成的偏差方向。
- 当前核验不足以证明重新采集会显著改变网格推荐排序，因此本轮不重新采集 60 个网格。

工程原型不可避免地存在数据覆盖、分类和接口限制。本项目追求的是边界清晰、统一口径下的相对质量，而不是无法由当前数据支持的绝对精确。

后续实施和展示需要保留：

- 请求缓存。
- 无 `AMAP_KEY` 时的 demo 模式。
- 查询摘要和数据限制说明。
- POI 分类可能重叠的说明。
- 关键词查询可能低估或扩大部分类型召回的说明。
- 所有评分结果均为同一查询口径下的相对评价。

## 7. 当前不做的内容

当前版本不做：

- 门牌号级推荐。
- 具体盈利承诺。
- 真实租金预测。
- 真实客流预测。
- 真实营收预测。
- 将省级或市级就业数据硬拆到 1km 评价网格。

报告和页面只能解释已有输入字段、评分结果和数据限制。
