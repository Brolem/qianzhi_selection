# 项目执行计划

本计划以根目录 `黔址优选_Codex多步执行指令.md` 为总控源文档。执行时按 Step 0 到 Step 18 逐步推进，每一步验收通过后再继续下一步。

## 总体目标

将项目从旧版 OSM/GIS 空间处理与两阶段筛选，迁移为“区县背景约束下的网格级多因子商业选址推荐模型”，并将前端改造成商业选址工作台。

## Step 17 当前实施状态

- 页面入口：`src/pages/report_center.py`。
- 报告引擎：`src/reporting/report_generator.py`。
- 支持默认社区便利店、默认轻餐饮和有效自定义评分方案。
- 只允许为有 POI 活动且具有有效排名的网格生成报告。
- DeepSeek 仅在按钮点击后调用；页面按方案和网格缓存结果，刷新不重复请求。
- 默认调用 `deepseek-v4-pro` 非思考模式，规定的暂时性错误才回退 `deepseek-v4-flash`。
- DeepSeek 使用 JSON Output 生成带证据字段的结构化分析素材；Python 校验后从真实评分记录写入数值并渲染 11 章 Markdown。
- 模型分析不得自行写入数值，不得把交通指标扩展为路网密度，不得混淆竞争压力与低竞争得分。
- JSON 空响应使用同一模型重试一次；结构、证据或内容质量失败不得回退 Flash。
- API 不可用时展示真实错误，用户可明确选择规则模板报告；模板结果不解释为 API 成功。
- 页面支持 11 章 Markdown 报告预览和下载。
- 2026 年 6 月 13 日真实 API 验证成功，Pro 返回完整报告，未触发 Flash 回退。

## Step 18 当前实施状态

- 一键入口：`scripts/run_pipeline.py`。
- 默认模式使用仓库已跟踪的 60 个真实 POI 样本网格，离线重建指标、评分、地图和两类 Top 1 模板报告。
- `--refresh-official` 重新处理六个官方 Excel。
- `--refresh-amap` 要求 `AMAP_KEY`，在线刷新三区边界、空间网格和三区各 20 个 POI 样本网格。
- `--with-llm` 要求 `DEEPSEEK_API_KEY`，生成两类 Top 1 DeepSeek 报告。
- `--serve` 仅在验收成功后使用 `0.0.0.0:8501` 启动工作台；端口占用时不启动第二个实例。
- 运行摘要写入 `outputs/results/pipeline_run_summary.md`，只记录密钥是否参与，不写入密钥值。
- 离线基线固定验收 3 个区县、790 个空间网格、60 个 POI 样本网格、41 个活跃网格和 19 个无活动网格。
- 交付说明见 `最终交付清单.md`，答辩流程见 `5分钟演示脚本.md`。

## Step 6 到 Step 7 的数据口径

Step 6 已完成 60 个样本网格的统一关键词查询。分类编码 6 网格核验用于检查关键词口径的偏差，不作为正式评分输入。

进入 Step 7 时遵循以下规则：

- 继续使用现有 60 网格关键词统计，不重新采集，不混用分类编码结果。
- 所有网格保持相同关键词、查询半径、分页和统计规则。
- 指标含义限定为同口径下的相对密度和相对强弱。
- 不把 POI 计数解释为区域真实、完整的设施总量。
- 分类编码核验结论作为数据限制和敏感性说明，不直接改变网格得分。

该决策优先保证工程原型的数据一致性、可复现性和相对比较质量。只有后续证据表明查询口径会显著改变推荐排序，才另行评估全量重新采集。

## 全项目禁止事项

1. 不声称获取全量高德 POI。
2. 不绕过或规避 API 限制。
3. 不把省级或市级就业数据硬拆到 1km 评价网格。
4. 不做门牌号级推荐。
5. 不写精准盈利预测。
6. 不编造真实客流、真实租金、真实营收。
7. 不把 demo 数据包装成真实官方数据。
8. 不删除旧文件而不备份。
9. 大规模重构后不跳过测试。
10. 不只改前端而忽略数据链路可运行性。
