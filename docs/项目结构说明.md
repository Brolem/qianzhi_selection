# 项目结构说明

## 结构原则

当前实现是唯一默认主线。v1 保留为可运行归档，但不得被当前入口、当前配置或当前业务模块导入。

项目按“数据层、管线层、模型层、报告层、前端层”划分职责，而不是继续按开发步骤堆放文件。`src/core/` 与 `config.yaml` 是横向支撑，不作为单独业务层。

## 五层职责

| 层级 | 目录或模块 | 职责边界 |
|---|---|---|
| 数据层 | `data/`、`outputs/` | 保存官方原始数据、高德缓存、主线处理数据、评分结果、地图和报告输出 |
| 管线层 | `src/pipeline/` | 将官方 Excel、高德区县边界和 POI 样本转换为当前主线处理数据 |
| 模型层 | `src/modeling/` | 生成指标、评分、排名、推荐等级、自定义方案和区域市场诊断 |
| 报告层 | `src/presentation/` | 生成地图 HTML、结构化 DeepSeek 报告和规则模板报告 |
| 前端层 | `src/app.py`、`src/web/` | 提供七页 Streamlit 工作台、跨页面选择状态和统一视觉组件 |

## 当前主线

### `src/core/`

- `config.py`：读取根目录 `config.yaml`，解析当前数据与输出路径。
- `profile_catalog.py`：读取默认及自定义评分方案元数据。

该目录不得依赖页面、地图或旧版实现。

### 管线层：`src/pipeline/`

- `amap_client.py`：高德 Web 服务客户端和缓存。
- `district_builder.py`：目标区县信息与边界。
- `grid_builder.py`：1km 评价网格。
- `poi_fetcher.py`：POI 采集、统计与分类编码核验。
- `official/`：官方 Excel 清洗及贵州省级背景报告。

该目录负责把外部数据转换为当前处理数据，不负责评分和页面展示。

### 模型层：`src/modeling/`

- `feature_engineering.py`：POI 计数到八项评分指标。
- `scoring_model.py`：默认及自定义六维权重评分。
- `interactive_scoring.py`：前端权重预算、即时预览与方案保存。

该目录读取处理数据并生成结构化评分结果，不直接调用 Streamlit。

### 报告层：`src/presentation/`

- `map_viz.py`：高德地图主链、Folium 回退和地图 HTML。
- `report_generator.py`：规则模板及 DeepSeek 结构化报告。

该目录负责把评分结果转换为可展示、可下载的地图和报告成果。

### 前端层：`src/web/`

- `decision_context.py`：在网格推荐、地图洞察和智能报告之间保存评分方案与网格选择。
- `pages/`：七个工作台页面。
- `ui/`：共享主题、标题栏、图例和页面组件。

`src/app.py` 只负责页面注册、视觉外壳和导航，是当前 Streamlit 唯一入口。

## v1 隔离区

```text
src/legacy/v1/
data/legacy/v1/
outputs/legacy/v1/
tests/legacy/v1/
docs/legacy/v1/
```

v1 使用 `src/legacy/v1/config.yaml`，不读取当前根目录配置。旧 OSM 数据、两阶段处理数据和旧运行结果均写入独立目录。

旧版命令见 `docs/legacy/v1/README.md`。

## 数据生命周期

```text
data/raw/official/
    ↓ 官方数据处理
data/processed/official/

高德行政区划与 POI
    ↓ 区县、网格、POI 管线
data/processed/
    ↓ 指标工程与评分
outputs/results/
    ↓ 地图与报告
outputs/figures/ + outputs/reports/
```

- `data/cache/amap/` 是本机请求缓存，不纳入 Git。
- `outputs/` 下当前运行结果默认不纳入 Git。
- `data/processed/` 中用于离线复现的真实样本输入继续纳入 Git。
- v1 文件只在 `legacy/v1` 目录内读写。

## 稳定入口

当前主线：

```powershell
python scripts/run_pipeline.py
streamlit run src/app.py
```

模块级入口：

```powershell
python -m src.pipeline.official.official_pipeline
python -m src.pipeline.district_builder
python -m src.pipeline.grid_builder
python -m src.pipeline.poi_fetcher
python -m src.modeling.feature_engineering
python -m src.modeling.scoring_model
python -m src.presentation.map_viz
python -m src.presentation.report_generator --profile convenience --template
```

## 依赖边界

1. 当前主线不得导入 `src.legacy.v1`。
2. v1 不得导入当前 `core`、`pipeline`、`modeling`、`presentation` 或 `web`。
3. 当前配置不得包含旧 OSM 路径、两阶段参数或旧权重。
4. 新功能按职责放入现有主线包，不新增版本并列目录。
5. 历史实现和历史说明只进入对应 `legacy/v1` 或 `history` 目录。

## Step 18 之后的维护边界

1. Step 18 是当前总控终点，不自动新增后续步骤。
2. 当前稳定入口继续保持为 `scripts/run_pipeline.py` 和 `src/app.py`。
3. 后续功能进入现有职责包，不新增并列版本目录或根目录重复模块。
4. 路线设想只有在真实数据、实现和验证完成后，才能写入当前能力文档。
