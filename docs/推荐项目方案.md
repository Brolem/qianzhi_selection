# 推荐项目方案

## 一、最终成果形态

v2 最终成果应是一个面向社区便利店和轻餐饮的商业智能选址工作台。系统以贵阳市典型区县为试点，把官方宏观经济指标、就业数据、高德行政区划和 POI 样本转化为 1km 评价网格推荐结果。

最终交付应包含：

- 数据底座说明。
- 1km 评价网格评分结果。
- 便利店 Top 10。
- 轻餐饮 Top 10。
- 区县分组对比。
- 地图洞察。
- 指标解释。
- 区域市场阶段与竞争状态诊断。
- Markdown 选址报告。

## 二、Demo 页面结构

建议页面结构：

1. 项目总览。
2. 数据底座。
3. 区域对比。
4. 网格推荐。
5. 地图洞察。
6. 智能报告。
7. 项目说明。

其中“网格推荐、地图洞察、智能报告”是核心演示页面。

Step 11 最初将工作台拆分为八个页面模块；Step 13–15 实施时确认原“选址分析”与“网格推荐”职责重复，因此删除独立页面并调整为七页导航。`src/app.py` 负责宽屏配置、共享视觉外壳、页面注册和导航，当前 Streamlit 1.58.0 使用 `st.Page` 与 `st.navigation`；旧版本运行环境退化为 sidebar radio。v1 页面已隔离到 `src/legacy/v1/app.py`。

Step 12 已增加 `src/web/ui/workbench.py` 共享视觉层和 `.streamlit/config.toml`。七页统一使用居中深色标题栏、蓝色强调、浅灰背景、白色内容面板和紧凑间距；桌面端采用参数区与结果区分栏，窄屏下按 900px 和 600px 两个断点逐步改为两列和单列。样式不依赖外部 CDN、外部字体或复杂前端框架。

评分方案不设置为全局固定业态状态。“网格推荐”“地图洞察”和“智能报告”分别使用页面内方案选择器，可读取默认便利店、默认轻餐饮和有效自定义方案。

## 四、页面重点

### 1. 项目总览

展示项目定位、业务对象、目标区县、推荐粒度和当前数据限制。首页将 15 类 POI 汇总为社区零售、餐饮消费、生活客群、商业办公和交通配套五个主题，以三区横向分组条形图展示原始总量；同时使用哑铃图对比 41 个活跃网格在各区县的便利店和轻餐饮平均分。15 类细分数量保留在区域对比页，首页图表只用于数据概览，不替代现场尽调。

### 2. 数据底座

展示官方宏观经济指标、官方就业数据、高德行政区划、1km 空间网格、POI 样本和网格评分输入之间的关系。当前高德区县边界、60 网格 POI 样本和评分输入已经生成；页面必须同时说明官方数据仅为贵州省级背景。

### 3. 区域对比

区县对比用于背景画像和结果分组，不作为最终推荐结论。页面应展示区县网格数量、POI 总量、平均分和各业态最高分网格。

当前读取 `district_summary_result.csv` 提供三区汇总，并根据 `grid_poi_counts.csv` 展示便利店与餐饮、学校/医院/商场/写字楼/小区、公交站/地铁站/停车场三组原始数量对比。区县平均分和 POI 数量只用于背景解释。

### 4. 网格推荐

展示便利店与轻餐饮的 Top 10 评价网格，并展示指标分解、主要优势、主要风险。页面不能只展示总分。

当前统一支持默认便利店、默认轻餐饮、已保存自定义方案和新建自定义方案。新建方案明确选择社区零售型或餐饮服务型模板，通过六项百分比数字输入分配 100 分权重预算；页面提供两套默认预设、平均分配、重置和确定性归一。即时预览直接调用 `score_profile()`，不写正式文件；正式保存要求权重合计精确为 100.00%，并使用现有四文件事务写入独立方案目录。结果区展示全局 Top 10、区县 Top 5、推荐等级、优势、风险和选中网格六维横向条形图。

区域诊断与综合评分相互独立。系统只使用 41 个有 POI 活动网格的消费潜力、就业/办公客群代理、共生业态、竞争压力和商业氛围计算全市统一三分位，将网格标记为市场空白型、待培育型、成熟商圈型或一般观察型，并单独给出过度竞争预警。页面展示类型数量，支持按市场阶段和竞争状态筛选；启用诊断筛选后展示全部匹配网格并保持原排名顺序。自定义权重只改变综合得分和排名，相同指标模板的诊断结果保持一致。

### 5. 地图洞察

地图以 790 个空间网格展示研究范围，并明确区分未采集、无 POI 活动、已评分和全局 Top 10。便利店、轻餐饮和有效自定义评分方案使用同一套 0-100 固定色阶。悬停展示 `grid_id`、`district_name`、得分、排名、市场阶段、竞争状态和主要优势；点击后展示推荐等级、六维指标、诊断摘要和主要风险。诊断标签不改变地图颜色和 Top 10 标记。

高德 JS API 2.0 作为地图主链，直接渲染 GCJ-02 区县边界、1km 网格和中心点，与高德行政区划和 POI 数据保持同源坐标。页面继续支持 Folium 兼容地图；仅该回退路径临时转换为 WGS84。地图只表达当前 POI 样本统一口径下的相对评分和数据覆盖状态。

高德 Web 服务使用 `AMAP_KEY`，地图页面使用独立的 `AMAP_JS_KEY` 和 `AMAP_JS_SECURITY_CODE`。凭据只从环境变量读取，不写入配置、源码和文档。

### 6. 智能报告

智能报告支持默认便利店、默认轻餐饮和有效自定义评分方案，只允许为有 POI 活动且具有有效排名的网格生成。页面在用户点击后调用 DeepSeek，默认使用 `deepseek-v4-pro` 非思考模式；仅在连接、超时、限流、服务端错误或模型不可用时回退 `deepseek-v4-flash`。鉴权、余额、请求参数和输入数据错误不得通过切换模型掩盖。

报告采用“结构化分析 + 程序渲染”链路。DeepSeek 通过 JSON Output 生成 11 个章节对应的分析素材、证据字段和经营建议，不直接写 Markdown，也不得自行复述或计算数值。Python 校验证据字段是否真实存在、竞争压力与低竞争得分方向、禁写内容和四项质量检查，再从 Step 8 结果写入真实分数、排名、权重、坐标和数据边界，最终渲染固定 11 章 Markdown。JSON 空响应仅对同一模型重试一次。

报告结构包含：

```text
一、评价网格基本信息
二、适配业态与推荐等级
三、交通可达性分析
四、消费潜力分析
五、就业/办公客群代理分析
六、共生业态分析
七、竞争压力分析
八、商业氛围与权重方案
九、主要优势与风险
十、经营建议
十一、数据来源与限制说明
```

所有结论必须来自 Step 8 评分字段、程序生成的区域诊断字段和结构化方案元数据。交通可达性只按公交站、地铁站和停车场 POI 解释，不扩展为路网密度或道路等级；竞争压力与低竞争得分必须分别解释。官方宏观与就业数据当前只有贵州省级地域范围，因此只用于整体市场背景和数据适用边界，不参与网格评分。就业/办公客群代理来自 POI 指标，不解释为真实就业人口密度。需求客群代理是消费潜力与就业/办公客群代理的均值，不是真实客流。DeepSeek 只能解释程序标签，不得修改市场阶段或竞争状态；API 不可用时可由用户明确选择规则模板报告。

当前页面实现位于 `src/web/pages/report_center.py`，报告引擎位于 `src/presentation/report_generator.py`。页面按评分方案与网格缓存生成结果，刷新不会重复请求；Markdown 报告可直接预览和下载。2026 年 6 月 13 日已使用用户级 `DEEPSEEK_API_KEY` 完成真实 Pro 调用验证，未触发 Flash 回退。

## 五、答辩叙事

推荐叙事：

```text
传统社区商业选址依赖经验
→ 官方公共数据提供区域市场背景
→ 高德 POI 和 GIS 补充空间样本
→ 区县限定研究范围和解释背景
→ 1km 评价网格统一评分
→ 便利店和轻餐饮采用差异化权重
→ 用户可基于社区零售型或餐饮服务型模板自定义六维权重
→ 全市统一三分位识别市场阶段和竞争风险
→ 地图展示空间分布
→ DeepSeek 报告解释推荐原因、权重和风险
```

## 六、功能优先级

| 优先级 | 内容 |
|---|---|
| P0 | 配置文件、高德客户端与缓存、默认离线复现、网格生成、POI 统计、默认评分、自定义权重、区域市场诊断、基础评分地图、网格推荐页 |
| P1 | 地图区县筛选、更多区域背景图表 |
| P2 | 报告导出 Word/PDF |
| P3 | 百度/腾讯 POI 备选、多源 POI 融合、H3 六边形、Location-Allocation 优化 |

自定义权重是赛题要求的核心适配能力。当前实现提供六维权重接口，并使用 `community_retail` 与 `food_service` 两类已有数据支撑的指标模板。银行等新增正式业态需先补充专属 POI、共生与竞争指标，不以更换方案名称代替数据建设。

## 七、避免事项

- 不把成果说成精确门店选址。
- 不声称获取全量高德 POI。
- 不把 demo 数据包装成真实官方数据。
- 不把省级或市级就业数据硬拆到 1km 评价网格。
- 不编造租金、客流、营收。
- 不把市场空白解释为保证盈利，不把过度竞争预警解释为企业真实经营状况。
- 不用区县平均分替代网格级推荐。

## 八、最终判断

v2 应呈现为一个可运行、可解释、边界清晰的社区商业智能选址工作台。项目价值不在于承诺具体门店收益，而在于把官方公共数据、POI 样本和 GIS 网格分析组织成可复现的选址辅助流程。
