# 推荐项目方案

## 一、最终成果形态

v2 最终成果应是一个面向社区便利店和轻餐饮的商业智能选址工作台。系统以贵阳市典型区县为试点，把官方宏观经济指标、就业数据、高德行政区划和 POI 样本转化为 1km 评价网格推荐结果。

最终交付应包含：

- 数据底座说明。
- 1km 评价网格评分结果。
- 便利店 Top 10。
- 轻餐饮 Top 10。
- 区县分组对比。
- 地图洞察。
- 指标解释。
- Markdown 选址报告。

## 二、Demo 页面结构

建议页面结构：

1. 项目总览。
2. 数据底座。
3. 选址分析。
4. 区域对比。
5. 网格推荐。
6. 地图洞察。
7. 智能报告。
8. 项目说明。

其中“选址分析、网格推荐、地图洞察、智能报告”是核心演示页面。

## 三、核心演示链路

```text
打开 Streamlit
→ 查看项目总览
→ 查看数据底座说明
→ 进入选址分析
→ 选择智能推荐
→ 选择便利店或轻餐饮
→ 选择云岩区、南明区、观山湖区或全部
→ 查看 Top 10 评价网格
→ 打开地图洞察
→ 选择一个 grid_id
→ 生成选址报告
→ 下载 Markdown 报告
```

## 四、页面重点

### 1. 项目总览

展示项目定位、业务对象、目标区县、推荐粒度和当前数据限制。首页应明确说明结果用于前期调研排序和经营研判，不替代现场尽调。

### 2. 数据底座

展示官方宏观经济指标、官方就业数据、高德行政区划、POI 样本、demo 数据和 legacy 数据之间的关系。需要明确 v2 高德链路仍需按执行计划实施。

### 3. 选址分析

采用步骤式流程：

```text
Step 1 选择应用场景
Step 2 设置分析参数
Step 3 查看推荐结果
Step 4 生成报告
```

第一版必须实现智能推荐；区域评估和单点评估只保留占位说明，不写成已完成能力。

### 4. 区域对比

区县对比用于背景画像和结果分组，不作为最终推荐结论。页面应展示区县网格数量、POI 总量、平均分和各业态最高分网格。

### 5. 网格推荐

展示便利店与轻餐饮的 Top 10 评价网格，并展示指标分解、主要优势、主要风险。页面不能只展示总分。

### 6. 地图洞察

地图展示评分颜色、重点网格和 tooltip。tooltip 至少包含 `grid_id`、`district_name`、得分、主要优势和主要风险。

### 7. 智能报告

报告结构应包含：

```text
一、评价网格基本信息
二、适配业态判断
三、交通可达性分析
四、消费潜力分析
五、就业/办公客群代理分析
六、共生业态分析
七、竞争压力分析
八、主要优势
九、主要风险
十、经营建议
十一、数据来源与限制说明
```

所有结论必须来自输入字段。缺失数据要明确写“当前未接入”。

## 五、答辩叙事

推荐叙事：

```text
传统社区商业选址依赖经验
→ 官方公共数据提供区域市场背景
→ 高德 POI 和 GIS 补充空间样本
→ 区县限定研究范围和解释背景
→ 1km 评价网格统一评分
→ 便利店和轻餐饮采用差异化权重
→ 用户可基于社区零售型或餐饮服务型模板自定义六维权重
→ 地图展示空间分布
→ 报告解释推荐原因和风险
```

## 六、功能优先级

| 优先级 | 内容 |
|---|---|
| P0 | 配置文件、高德 API demo 模式、网格生成、POI 统计、默认评分、自定义权重、选址分析页 |
| P1 | 地图洞察、智能报告、区域对比、视觉样式 |
| P2 | 报告导出 Word/PDF |
| P3 | 百度/腾讯 POI 备选、多源 POI 融合、H3 六边形、Location-Allocation 优化 |

自定义权重是赛题要求的核心适配能力。当前实现提供六维权重接口，并使用 `community_retail` 与 `food_service` 两类已有数据支撑的指标模板。银行等新增正式业态需先补充专属 POI、共生与竞争指标，不以更换方案名称代替数据建设。

## 七、避免事项

- 不把成果说成精确门店选址。
- 不声称获取全量高德 POI。
- 不把 demo 数据包装成真实官方数据。
- 不把省级或市级就业数据硬拆到 1km 评价网格。
- 不编造租金、客流、营收。
- 不用区县平均分替代网格级推荐。

## 八、最终判断

v2 应呈现为一个可运行、可解释、边界清晰的社区商业智能选址工作台。项目价值不在于承诺具体门店收益，而在于把官方公共数据、POI 样本和 GIS 网格分析组织成可复现的选址辅助流程。
